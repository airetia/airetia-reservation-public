## 1. 料金・チケットルール

### 1.1 チケット基本仕様

| 項目 | 値 |
|------|----|
| 単価 | 500 円/枚（税抜・MVP 期間固定） |
| 最小購入枚数 | 1 枚 |
| 最大購入枚数 | 制限なし |
| 購入方法（MVP） | 管理者による手動付与（振込確認後） |
| 購入方法（Phase2 以降） | オンライン決済（Stripe） |

### 1.2 有効期限
```
有効期限 = 購入日 + 1年間（翌年同日 23:59:59 JST まで）
```

| 購入日 | 有効期限 |
|--------|---------|
| 2024/2/29（閏年） | 2025/2/28 23:59:59 |
| 2026/12/31 | 2027/12/31 23:59:59 |

**予約時チェック**: `チケット有効期限 >= サービス開始時刻`

期限超過後は自動論理削除（物理削除なし・永続保持）。

### 1.3 消費ルール

**消費タイミング**: 予約確定（CONFIRMED）時に即座消費

**消費枚数**:
```
消費枚数 = サービス設定消費枚数 × 予約人数
```

**優先順位**: 有効期限が近いチケットから消費（FIFO）

**残高チェック**:
```
利用可能チケット数 >= 消費枚数  → 予約可能
利用可能チケット数 < 消費枚数   → 予約不可
```

### 1.4 プロバイダーのチケット扱い

プロバイダーがサービスを提供してもチケット残高は増加しない。
報酬は「月末集計 → 翌月 10 日払い」の現金（換算計算のみチケット単価を使用）。

## 2. 予約ルール

### 2.1 予約解放
```
毎日 0:00 JST に「現在日 + 2ヶ月」のサービスを予約可能にする
```

N ヶ月後の計算ルール → [§6.2](#62-nヶ月後の計算)

| 現在日 | 解放日 |
|--------|--------|
| 1/15 | 3/15 |
| 1/31 | 3/31 |
| 12/31 | 2/28（平年）/ 2/29（閏年） |

### 2.2 予約上限

Participant 1名あたりの上限（2段階制御）:

```
① CONFIRMED + PENDING 合計 ≤ 90件
② PENDING のみ         ≤ 10件
```

エラーメッセージ:
- PENDING が 10 件に達している場合: `「リクエスト上限（10件）に達しています。確定後に再度リクエストしてください」`
- 合計が 90 件に達している場合: `「予約上限（90件）に達しています」`
- 両方同時に該当する場合: PENDING 上限のメッセージを優先

**チェック順序**: PENDING 上限 → 合計上限 の順で確認する。

### 2.3 1日予約上限
```
Participant 1名あたり、1日（0:00〜23:59 JST）最大 3 件
基準: サービス開始時刻
```
エラー: `「[利用者名]は[日付]に既に 3 件のサービスを予約しています」`

### 2.4 時間重複チェック
```
既存予約: [A_start, A_end)
新規予約: [B_start, B_end)
重複 = (B_start < A_end) AND (B_end > A_start)
A_end == B_start → 重複しない（許可）
```

| 既存 | 新規 | 判定 |
|------|------|------|
| 10:00-11:00 | 11:00-12:00 | ✅ 可 |
| 10:00-11:00 | 10:59-12:00 | ❌ 不可 |

### 2.5 先着順・定員管理

- 同時予約競合: DB トランザクション制御で先着優先
- 予約可能数: `定員 - 現在の確定予約数（CONFIRMED）`

### 2.6 報告書

#### 完了報告
- 報告可能期間: `サービス終了 15 分前 〜 サービス終了 24 時間後`
- 記載内容（各 1000 文字以内）:
  - 利用者へのフィードバック（公開）
  - 利用者の特徴（全プロバイダー共有）
  - 詳細メモ（報告者のみ閲覧）

#### 無断キャンセル報告
- 報告可能タイミング: `サービス開始 15 分後〜`
- 報告完了時: 利用者にペナルティ即座適用・該当枠を空き枠として開放

## 3. キャンセルルール

### 3.1 キャンセルポリシー

サービス開始時刻を基準とする。**境界ちょうどは返還率が高い方を適用**（例: ちょうど 24 時間前 → 100%）。

| キャンセル時期 | 返還率 | 返還チケット有効期限 |
|--------------|--------|-------------------|
| 24 時間以上前（>= 1440 分） | 100% | 元の有効期限 |
| 24 時間未満〜12 時間前（720〜1439 分） | 50% | キャンセル日 + 7 日 23:59:59 |
| 12 時間未満〜30 分前（30〜719 分） | 20% | キャンセル日 + 7 日 23:59:59 |
| 30 分未満（< 30 分） | 0% | − |
| 無断キャンセル | 0% | − |

**PENDING 状態のキャンセル**: チケット未消費のため返還なし・ペナルティなし。

**利用停止中ユーザー**: 24 時間以上前のキャンセルのみ可能。それ以外は無断キャンセル扱い。

### 3.2 返還枚数計算
```
返還枚数 = floor(消費枚数 × 返還率)   ← 小数点以下切り捨て
```

| 消費枚数 | 返還率 | 計算 | 返還枚数 |
|---------|--------|------|---------|
| 4 | 100% | floor(4.0) | 4 |
| 4 | 50% | floor(2.0) | 2 |
| 4 | 20% | floor(0.8) | 0 |
| 5 | 20% | floor(1.0) | 1 |

### 3.3 返還チケット有効期限
```
返還チケット有効期限 = MIN(計算有効期限, 元チケット有効期限)
```

例:
```
元チケット有効期限: 2026/3/31 23:59:59
キャンセル日: 2026/3/20（返還率 50% 適用）
計算有効期限: 2026/3/27 23:59:59
→ 返還有効期限: 2026/3/27 23:59:59（短い方）
```

### 3.4 プロバイダー都合のキャンセル
```
返還率: 100%（時期に関わらず）
返還チケット有効期限: 元の有効期限（短縮なし）
利用者へのペナルティ: 一切なし
```

**プロバイダーへの累積警告（年間）**:

| 回数 | 措置 |
|------|------|
| 3 回 | 警告メール |
| 5 回 | 管理者面談 |
| 10 回以上 | プロバイダー機能一時停止検討 |

## 4. ペナルティルール

### 4.1 要注意マーク

- 付与条件: 無断キャンセル 1 回につき 1 つ
- 有効期間: `付与日時 + 3ヶ月`
- 自動解除: 毎日 1:00 JST のバッチで無効化

### 4.2 自動ペナルティ（直近 3ヶ月の無断キャンセル数）

| 無断キャンセル回数 | ペナルティ | 期間 |
|-----------------|-----------|------|
| 3 回 | 利用停止 | 7 日間 |
| 5 回 | 利用停止 | 90 日間 |
| 10 回以上 | アカウント削除 | 永久 |

### 4.3 利用停止の範囲

**制限**: 新規予約作成・既存予約変更
**制限なし**: 既存予約閲覧・24 時間前までのキャンセル・プロフィール編集・チケット購入

### 4.4 停止解除

- 自動解除: 停止期間終了後に自動解除（バッチ処理）
- 手動解除: 管理者のみ・解除理由記録必須・監査ログに記録

## 5. プロバイダールール

### 5.1 登録・承認

#### 5.1.1 申請者入力項目

> 氏名・ふりがな・生年月日・住所・郵便番号・電話番号は `members` テーブルに保存。その他は `providers` テーブルに保存。

| 項目 | 必須 | 制約 | 保存先 |
|------|------|------|--------|
| 氏名（姓・名） | ○ | 各 50 文字以内 | members |
| ふりがな（姓・名） | ○ | 各 50 文字以内・ひらがな | members |
| 生年月日 | ○ | 有効な日付 | members |
| 住所 | ○ | 255 文字以内 | members |
| 郵便番号 | ○ | 数字 7 桁 | members |
| 電話番号 | ○ | 数字 10〜11 桁 | members |
| 出身高校 | ○ | 255 文字以内 | providers |
| 出身大学・専門学校 | △ | 255 文字以内 | providers |
| 保有資格 | △ | 最大 5 件・各 255 文字以内 | providers（JSON） |
| 賞歴・実績 | △ | 最大 5 件・各 255 文字以内 | providers（JSON） |
| アピールポイント | ○ | 2000 文字以内 | providers |

#### 5.1.2 必要書類

| 書類 | 種別コード | 形式 | 上限サイズ |
|------|-----------|------|---------|
| 身分証明書 | `IDENTITY` | JPG / PNG / PDF | 10 MB |
| 署名済み契約書 | `CONTRACT` | PDF | 10 MB |
| 口座情報 | `BANK_INFO` | JPG / PNG / PDF | 10 MB |

3 書類すべてのアップロード完了後に `PENDING_DOCUMENTS` → `PENDING` へ自動遷移し、管理者審査が開始される。

#### 5.1.3 審査期間・結果

**標準審査**: 3 営業日以内 / **個別対応（追加確認等）**: 7 営業日以内

| 結果 | ステータス | 処理 | 再申請 |
|------|----------|------|--------|
| 承認 | `APPROVED` | 承認メール送信・機能有効化 | − |
| 却下 | `REJECTED` | 却下理由を明記してメール送信 | 却下日 + 1ヶ月後 |
| 保留 | `ON_HOLD` | 不足内容を具体的に明記してメール送信 | 即時可 |

**重複検知**: 以下いずれかが一致した場合は同一人物として扱い、重複申請を拒否する。
- 電話番号
- メールアドレス
- 氏名 + 生年月日

#### 5.1.4 再申請

- `ON_HOLD`（保留）からの再申請: 即時可。ON_HOLD 理由で指摘された不備を修正して再提出。
- `REJECTED`（却下）からの再申請: 却下日から 1ヶ月後に再申請可。

### 5.2 空き枠管理

登録可能期間: `当日 〜 3ヶ月後の月末`

| 状態 | 削除 | 時間変更 | 定員変更 | 内容変更 |
|------|------|----------|----------|---------|
| 予約 0 件 | ✅ | ✅ | ✅ | ✅ |
| 予約 1 件以上 | ❌ | ❌ | △ ※ | ❌ |

※ 定員変更条件: `新定員 >= 既存予約数`

### 5.3 報酬計算

```
月間報酬 = floor( Σ(対象チケット枚数) × 500円 × 0.4 ) − 振込手数料
報酬率 = 40%
```

| 対象 | 計算方法 |
|------|---------|
| 完了サービス | `bookings.tickets_consumed`（実消費枚数）× 報酬率 |
| 無断キャンセル（元消費予定 6 枚以上） | 固定 1 枚 × 報酬率（`bookings.tickets_consumed` で判定） |
| 無断キャンセル（元消費予定 5 枚以下） | 報酬なし |
| プロバイダー都合・利用者都合キャンセル | 対象外 |

> `bookings.tickets_consumed` は予約作成時に確定した消費枚数を記録する。キャンセル・NO_SHOW後も値は保持する。

**支払いサイクル**: 月末締め・翌月 10 日払い

### 5.4 利用制限

- プロバイダーは自分が提供するサービスへの予約不可（システムレベルで禁止）
- 他プロバイダーのサービスへの予約は可能（チケット消費）
- プロバイダー登録に上限なし（重複のみ禁止）

## 6. 時間・期間計算ルール

### 6.1 タイムゾーン原則
```
すべての業務判断は JST（UTC+9、Asia/Tokyo）を基準とする
DB 保存: UTC / API 応答: UTC（ISO 8601）/ UI 表示: JST
```

### 6.2 N ヶ月後の計算
```
同日ベース（該当日なしの場合は月末）
```

| 起算日 | +N | 結果 |
|--------|-----|------|
| 1/31 | +1 | 2/28（平年）/ 2/29（閏年） |
| 3/31 | +1 | 4/30 |
| 1/15 | +2 | 3/15 |

### 6.3 N 日後の計算
```
起算日を含まない: 1/15 の 3 日後 = 1/18
```

### 6.4 UI 日時表示形式

| 種別 | 形式 | 例 |
|------|------|----|
| 日付（長） | `YYYY年MM月DD日（曜）` | `2026年1月10日（金）` |
| 時刻 | `HH:MM`（24 時間） | `14:00` |
| 日時（フル） | `YYYY年MM月DD日（曜） HH:MM` | `2026年1月10日（金） 14:00` |

## 7. 権限・認可ルール

### 7.1 管理者（ADMIN）

**可能な操作**:
- システム全体の管理・統計閲覧
- すべてのデータへのアクセス・代理操作（予約・空き枠・サービスのキャンセル・編集・登録等）
- ペナルティ解除
- プロバイダー申請承認・却下・保留・停止
- メンバー・Participant・プロバイダーの作成・編集・削除
- チケット手動付与・調整
- 監査ログ閲覧・問い合わせ対応

**禁止事項（Admin は Member ではないため利用不可）**:
- チケットの取得・消費
- サービスの予約・利用
- Participant の作成・利用
- プロバイダーとしてのサービス提供

**管理者アカウント追加**: ログイン済みの管理者が管理画面から新規登録（自己登録不可）。
**代理操作は全て監査ログに記録される。**

### 7.2 メンバー（MEMBER）

**可能な操作**:
- 自分の情報・チケット・予約・Participant の管理
- Provider 機能: 管理者承認後に有効化
- Parent 機能: 子ども Participant 登録時に自動付与

### 7.3 データアクセス制御

| アクター | アクセス範囲 |
|---------|-----------|
| 管理者 | 全ユーザー情報（書類含む） |
| プロバイダー | 予約確定した利用者の最小限情報（氏名・年齢・要注意マーク・自分の指導メモ） |
| 保護者 | 自分に紐づく Participant のみ |

**プロバイダーが閲覧不可**: 保護者の住所・電話番号・メール・チケット残高

## 9. 通知設定

デフォルトは全通知 ON。将来的に一部デフォルト変更の可能性あり。

| 通知種別 | デフォルト | DB カラム |
|---------|---------|---------|
| 予約確定 | ON | `notify_booking_confirmed` |
| 予約キャンセル | ON | `notify_booking_cancelled` |
| 前日リマインド | ON | `notify_booking_reminder` |
| チケット期限切れ警告 | ON | `notify_ticket_expiry` |
| ペナルティ付与 | ON | `notify_penalty_applied` |
| プロバイダー審査結果 | ON | `notify_provider_status` |
| 報告書フィードバック受信 | ON | `notify_report_feedback` |

メンバー登録時に `notification_settings` レコードを自動生成する。
